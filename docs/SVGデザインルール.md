# note用SVGデザインルール（vibe-coding-records）

スマービー（よつば_オウンドメディア）のSVGルールをベースに、note連載「vibe-coding-records」用として固めたもの。過去回（intro〜11話）の実物から抽出した。新しいSVG図解を作るときは、まずこの文書に合わせる。

---

## 1. 前提・用途

- noteは記事本文に生のSVGコードを貼れない。必ずPNGに変換して画像として配置する。
- 図解はH2見出しの直後に1枚置くのが基本（連載のデフォルト配置）。
- 図解＝SVG、雰囲気カット＝画像生成AI、と役割を分ける。フロー図・概念図・比較表はSVGで作る。

---

## 2. 画像サイズ（viewBox）※最重要

- 基準は **16:9 の 1920×1080**。PNG化したとき高精細で、過去の10話以降がこの形。新規はこれを既定にする。
- 1280×720（同じ16:9）も可。ただし後述のとおりフォントが小さくなるので、情報量が多い図は1920を推奨。
- **文字が窮屈なら、画像サイズは問わない。** 最小フォントを下回ってまで詰め込むより、入れたい情報が読める大きさを優先する。
  - 具体策：横幅1920は固定したまま、縦だけ必要な分だけ伸ばす（例 1920×1200、1920×1280）。これで16:9は崩れるが、横並びの収まりは保てる。
  - それでも **できる限り16:9を目指す**。まずは要素を減らす・2段組にするなどで16:9に収める工夫を先に試し、どうしても無理なときだけ縦を伸ばす。
- 過去の揺れ：07〜09話は本文図解が1280×670（16:9よりやや低い）だった時期がある。これは現行の基準ではない。今後は16:9に揃える。
- アイキャッチは本文図解と別枠。note記事の見出し画像用に1280×720（最新）で作る。本文図解のサイズ基準とは混同しない。

---

## 3. フォントサイズ ※最重要

数値は **1920×1080 を基準** とした目安（最新10話の実測）。

| 用途 | サイズ（1920基準） |
| --- | --- |
| 左上のタイトル | 60〜62 |
| カードのヘッダー帯・強調基盤の帯 | 52〜54 |
| カード内の見出し・本文 | 46〜50 |
| 補足・注記 | 40〜46 |
| フッターキャッチの一文 | 34 |
| これ未満は使わない（最小ライン） | 32 |

- 1280×720で作る場合は、上の数値を **約0.67倍** にする（タイトル40前後／本文22〜26／最小22）。
- 過去に1280サイズで13〜16pxまで落とした図があるが、小さすぎなので踏襲しない。1280でも最小は22程度を守る。
- **窮屈なら、フォントを最小ライン未満に縮めない。** 代わりに2.の方針で画像の高さを足す、または要素を減らす。読めることが最優先。

## 4. 配色

緑系は使わない。青を主役、オレンジ（アンバー）をアクセントにする。

| 役割 | カラーコード |

| 背景 | #f8f9fa |
| メインの青（カード枠線・ヘッダー帯） | #5da8d4 |

| 薄い青の塗り | #eff6ff / #dbeafe |

## 5. レイアウトの定番パターン

- **ヘッダー**：左上にタイトル（x=80, y=80, dominant-baseline="hanging"）。その真下にオレンジの短い下線（line x1=80 y1=172 x2=280 y2=172, stroke="#f59e0b", stroke-width="5"）。この組み合わせを毎回つける。
- **カード**：白塗り（#fff）＋青枠（stroke="#5da8d4", stroke-width="3"）＋角丸（rx=20〜24）。上部に青のヘッダー帯（角丸の下端を四角でもう一枚重ねて、帯の下辺を直角にする）。帯の中に白抜きアイコン＋白文字のカード名。
  - **アイコンとカード名は、2つでひとまとまりとして帯の水平中央に置く。** カードに対して左右の余白が均等になるよう配置する。片寄せにしない。
  - **アイコンと文字の間隔は詰める。** 離しすぎない（目安：アイコン1文字分以内）。
  - これは毎回指摘が出るポイントなので、初稿の時点で必ず守る。
- **フロー矢印**：直線（line）＋三角（polygon）。色は #3a7ba8 か #5da8d4、太さ6前後。
  - **斜め線は使わない。** 矢印・コネクタは水平・垂直の直線と直角だけで組む。分岐も、縦線と横線を組み合わせたL字にする。斜めはいびつに見えやすい。これも初稿から守る。
- **チェック／バツ**：円（circle）の中に、チェックはpolyline、バツはline2本。チェックは青、バツはグレー。
- **強調の基盤ブロック**：薄オレンジ塗り（#fef3e2）＋オレンジ枠（#f59e0b）＋オレンジ帯。「これがいちばん言いたいこと」を下段にどんと置くときに使う。
- **フッターキャッチ**：いちばん下に、白い角丸の帯（stroke="#fde6c1"）＋左端にオレンジの小さい丸（circle r=10, fill="#f59e0b"）＋一文のまとめ（font-size 34）。これがnote独自の締めの作法。毎回入れる。

---

## 6. アイコン

- これまで使ってきたMaterial Symbols風のパスを流用する。新規に自作しない。
- 帯の中では白抜き、基盤ブロックではオレンジ。大きさは scale 2.2〜2.8 程度。

---

## 7. テキストの作法

- 中央寄せは text-anchor="middle"、上下中央は dominant-baseline="central"。
- 改行は tspan ではなく text 要素を複数並べて行ごとに置く（PNG化で崩れにくい）。
- 1行に詰め込みすぎない。長い文は2行に分ける。

---

## 8. SVGルート要素の属性

最新回の書き方に合わせる：

```
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1920 1080" width="100%" preserveAspectRatio="xMidYMid meet" role="img" aria-label="図のタイトル">
```

- aria-label には図の主旨を日本語で入れる。

---

## 9. PNG化と保存

- SVGは `images/svg/<記事番号>-<連番>.svg` に保存（例 12-01.svg）。
- `python scripts/svg2png.py --all` でPNG化（Retina2x）。`images/png/` に出力される。
- 記事本文ではPNGを参照する。noteには生SVGを貼らない。

---

## 10. やらないこと

- 緑系の色を使う。
- フォントを最小ライン未満（1920基準で32px未満／1280基準で22px未満）に縮める。
- noteに生のSVGコードを貼る（必ずPNG化）。
- アイコンを自作する（既存パスを流用）。
- 1枚に情報を詰め込みすぎる（読めなくなるくらいなら分割するか高さを足す）。
- 斜めの矢印・コネクタを使う（必ず水平・垂直の直線と直角で組む）。
- カード内でアイコンと見出しを片寄せにする／間隔を空けすぎる（2つでひとまとまりにして中央へ、間隔は詰める）。
